# 2026-10-21

## 案例发布「网络开小差了」根因与修复（21:1x，用户实测发 QR 图片失败）
- 根因：昨天建 `yb_cases` 时 `owner_id` 没加默认值——`yb_posts.owner_id` 的 DEFAULT 是 `auth.uid()`（客户端 insert 不传 owner_id，靠库内默认填作者），yb_cases 缺它 → NOT NULL 违反（23502）→ 长英文报错被 errMsg 收敛成「网络开小差了」
- 修复：`ALTER TABLE yb_cases ALTER COLUMN owner_id SET DEFAULT auth.uid()`（migrate 即时生效，无需发版）；cloud.js publishCase catch 里加 console.warn 输出原始错误 code+message（errMsg 收敛后线上排障只能靠它）
- 验证：冒烟 insert（显式 owner_id）+ delete 清理成功；线上 e2e 14/14
- 教训：**给客户端可写的表加 owner_id 类字段时，默认值必须是 auth.uid()，与 yb_posts 对齐**；新表上线前最好用 write 模式做一次冒烟 insert

## 后台「扫码卡二维码」始终传不上去（21:1x，已修复上线）
- 排查：`yb_settings` 表**整个是空的**（连 license_* 证照键都没有）→ admin_set_setting 的 RPC 从来没成功落库过；之前「看起来成功」全是 localStorage 缓存假象（yrb_jj_qr / yrb_license_v1）
- 对照：小参数 RPC（admin_verify_password 验管理密码）能用 → is_admin() 正常、RPC 通路正常；唯一差异是 payload 体积（二维码/证照 dataURL 几百 KB~1MB）
- 结论：大 POST 体被 .cn 代理/网关拦掉（挂起或吞错误，前端旧代码无超时无日志，表现为「始终传不上」）
- 修复 admin.js：
  1) shrinkImage → shrinkToBudget(file,maxPx,budgetKB,preferPng)：二维码 560px/150KB（干净 PNG 保无损，超预算转 JPEG 循环降质缩边）；证照 1000px/200KB
  2) rpcT(fn,args,ms)：RPC 20 秒超时 + 原始错误 console.warn（errMsg 类收敛吞错误的老问题，后台必须留原始日志）
  3) qrUpload/licUpload 错误提示区分「非管理员 / 超时 / 其他」
- 验证：temp/qr_shrink_check.js（注入私有函数）——1.1MB 噪点截图→95KB、纯 QR PNG 21KB→27KB、照片 217KB→134KB，全部达标且 <120ms；本地+线上同测
- 注意：admin.js 是 IIFE，函数私有，测试须 addScriptTag 注入源码片段
- 若压缩后仍超时：说明网关限制比 200KB 更低或另有拦截层——看用户端控制台 [二维码上传] 原始错误日志再定位
