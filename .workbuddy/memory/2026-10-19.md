## 二维码「能上传、但没有换」排查与修复（10:3x-11:4x）
用户反馈：后台能上传二维码，但前台家教页没换。

### 根因（两个，都很隐蔽）
1. **读取时序 bug**：`jiaojiao.js` 的 `loadQR()` 在 boot 时直接取 `YRB_CLOUD.client`，而 cloud.js 的 SDK 是**异步加载**的，此刻 `client === null` → 旧代码 `if(!C.client) return;` **直接放弃且永不重试** → 云端换过的二维码前台永远读不到（刷新也不行，因为每次 boot 都早于 SDK 就绪）
2. **SDK 接口误用**（更严重）：查询要走 `YRB_CLOUD.client.database.from(...)`，但 `food.js`(3处)、`license.js`(1处)、`profile.js`(4处) 写成 `client.from(...)` → `is not a function`，全部被 try/catch 静默吞掉 → 资质证照云端读取、个人资料云同步、礼物收件箱全都"看着正常其实没通"

### 修复
- `cloud.js`：`ready=true` 后广播 `yrb-cloud-ready` 事件（供所有增强层重试）
- `jiaojiao.js`：`loadQR()` 改为「本地缓存秒开 + client 未就绪则 250ms×48 轮询 + 监听 yrb-cloud-ready」，新增模块变量 `qrCurrent`，`boot()` 建页后自动补回（页面重建也不丢）；`yrb-jj-qr` 事件带 `detail.value` 立即生效
- `admin.js` `qrUpload()`：上传前校验登录态；错误分类提示（42501→"当前登录账号不是管理员（需用 180****5855 登录）"）；**写后回读校验**，云端值不一致就不谎报成功；事件带 detail
- `food.js` / `license.js` / `profile.js`：`client.from` → `client.database.from`，并补 `!C.client.database` 守卫

### 验证
- 用 migrate 直接往 yb_settings 写一条 1×1 测试 dataURL → 线上家教页实测显示测试图（natural=1）→ 说明读路径已通
- 删除该行 → 自动回落默认 `assets/jiaojiao-qr.png`（natural=290）
- jiaojiao_check 33/33（新增 I 段：本地缓存二维码启动即生效）；profile 14/14、license 18/18、food 21/21（线上）
- 部署 https://bd61e8ee.yurenbang.pages.dev，版本戳 202610191144
