# 育人帮 · 一键发布（发布守卫）

## 这个技能解决什么问题

以前发布 = 同步 + 部署 + 人工点几下确认。新版本一旦有问题，是用户先发现、再反馈、再排查——这段时间线上是坏的。
现在发布是一个**有守卫的动作**：不通过全量校验就不部署；部署后跑真实浏览器自检；自检不过自动回滚并明确告知。
因此**任何上线都必须走这条流程**，不要手工拼命令逐个跑。

## 何时使用

- 用户说「发布 / 上线 / 部署 / 推到线上 / 更新网站」
- 改动完成后需要确认线上是否健康（用 `--check` 只体检）
- 线上疑似坏了，需要判断是否回滚

## 前置条件

1. 工作目录是 `E:/育人帮`（脚本里硬编码了这个根路径）
2. `E:/育人帮/.venv/Scripts/python.exe` 存在（没有时提示用户先建虚拟环境）
3. **改动只落在 `yurenbang-app/`**，绝不直接改 `deploy-cn/`——它是产物，会被同步覆盖

## 标准发布流程

在**后台**执行（整个流程 5~15 分钟，用前台短超时会被掐断）：

```bash
cd /e/育人帮 && PYTHONUTF8=1 PYTHONIOENCODING=utf-8 \
  .venv/Scripts/python.exe -u temp/release.py
```

也可用本技能自带封装（等价，自动设置 UTF-8 环境变量）：

```bash
<E:/育人帮/.venv/Scripts/python.exe> E:/育人帮/.workbuddy/skills/yrb-release/scripts/run_release.py
```

参数：

| 参数 | 用途 |
|---|---|
| （无） | 完整发布：备份 → 校验 → 部署 → 等传播 → 自检 → 失败回滚 |
| `--check` | 只跑线上自检，不发布（约 40 秒，适合日常巡检） |
| `--no-rollback` | 发布但失败不回滚，**仅在排查问题时用** |
| `--skip-sync` | 跳过同步（部署包已确认就绪时） |

## 七个阶段怎么判读

| 阶段 | 说明 | 出问题时的含义 |
|---|---|---|
| ① 备份 | 无 lastgood 时才备份改动前内容到 `.cache/deploy_prev` | 只是兜底 |
| ② 同步 + 全量校验 | `sync_deploy.py`：复制源码、补回 `.cn` 域名改写、打包 bundle、加 `?v=` 版本戳、16 项断言 | **校验不过直接中止，线上未动**，改源码重跑即可 |
| ③ 部署 | `cf_browser_deploy.py`（Playwright 驱动 wrangler） | 多半是 wrangler 登录过期 |
| ④ 等边缘生效 | 轮询 `/build.json` 直到等于目标构建号，最多 150 秒 | 上传成功 ≠ 全球边缘已切，**不要因为"刚部署完还是旧构建号"就判失败** |
| ⑤ 生产自检 | `prod-check.js`：真实 Chrome 打开线上，检查免疫系统各层、构建号一致性、新旧混载、骨架、栏目、登录入口 | 单次失败会间隔 10 秒复检一次 |
| ⑥ 自动回滚 | 自检失败时按清单**覆盖式**恢复 `.cache/deploy_lastgood` 并重新部署 | 回滚全程不删除任何文件 |
| ⑦ 回滚后复检 | 确认线上恢复 | 仍不健康 = 需人工介入 |

## 失败处理决策表

| 现象 | 处理 |
|---|---|
| ② 校验未通过 | 读输出里失败的断言 → 改 `yurenbang-app/` 源码 → 重跑。**线上没动过** |
| ③ 部署失败 | 先跑一次 `wrangler whoami` 触发 OAuth 刷新再重试；网络抖动可重试 1~2 次 |
| ④ 传播超时（仍读到旧构建号） | 不要重复部署，先跑 `--check`，多为边缘传播慢 |
| ⑤ 自检个别项 ✗ | 看 `detail` 定位；若是"全部功能层健康"里点名的某个 `YRB_*` 层，优先查该层脚本 404 或初始化报错 |
| 已自动回滚 | 线上已回到上一版。修好问题再发布；不要用 `--no-rollback` 把坏版本留在线上 |
| 回滚后仍不健康 | 立即人工介入，不要反复部署 |

## 铁律

1. **不要手动 `cp` 覆盖 `deploy-cn/`**——`.cn` 域名改写、worker 白名单、bundle 打包、版本戳都在同步里做，手抄必丢（历史上踩过 4 次）
2. **不要删除/清空 `.cache/deploy_prev`、`.cache/deploy_lastgood`**——它们是回滚的唯一依据
3. **新增功能层必须同步在 `assets/health.js` 的 `LAYERS` 里加探针**，否则不算交付：`prod-check` 只信免疫系统的体检结果
4. **构建号由脚本生成**（`build.json`、页面 `<meta name="yrb-build">`、bundle 头 `YRB_BUILD` 四处强一致），不要手改任何一处
5. **图片等静态资源必须带 `?v=` 版本戳**才能穿透 Cloudflare 4 小时边缘缓存；同步脚本会自动加，手写引用时要自己加
6. 所有对 `.cn` 的资产验证请求必须带浏览器 UA，否则会被 CF bot 防护 403

## 配套文件位置

- `temp/sync_deploy.py` — 同步 + 校验
- `temp/cf_browser_deploy.py` — 部署执行体
- `temp/prod-check.js` — 生产自检（退出码 0/1 供守卫判断）
- `temp/release.py` — 总守卫
- `一键发布.bat` — 用户双击入口（走同一个 release.py）
- `references/troubleshooting.md` — 历史踩坑与排查细节，遇到疑难先读它
