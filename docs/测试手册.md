# 测试手册

> 配套：`测试收敛清单.md`（189 个脚本的盘点与分级）、`开发手册.md`。
> 原则：**一条命令知道有没有事**，其余测试按需跑、不乱跑。

---

## 1. 三级门禁

```bash
npm run verify:fast    # ≈0.8s：语法 28 文件 + 状态边界 54 处 + 层登记 12 项 + 仓库卫生（提交时自动跑）
npm run verify         # ≈2s：再加部署一致性 65 项（推送时自动跑）
npm run verify:e2e     # ≈110s：再加 8 项浏览器端到端（需 8796 + 8793 两个服务）
```

远端 GitHub Actions 在每次 push 到 main 时跑「标准档」，Ubuntu 兜底。
（e2e 只在本地跑：测试硬编码了 Windows 的 Chrome 路径与本机 playwright-core，Ubuntu 上没有。）

## 2. 端到端测试必须先起服务

两条线，对应两种被测对象：

```bash
npm run serve                              # 8796：源码 yurenbang-app/（开发时用，能测未打包的层）
python -m http.server 8793 --bind 127.0.0.1  # 8793：项目根，走 /deploy-cn/（验打包产物）
npm run verify:e2e
```

| 端口 | 被测对象 | 跑哪些 |
|------|----------|--------|
| 8796 | 源码 | casedit 55、state-guard 13、longimg 21 |
| 8793 | 部署包 | bundle 7、chips 11、cover 10、guard 8、deepcheck 7 |

服务没起时，**整组跳过而不是失败**（返回「跳过」），这是刻意设计——不阻塞纯逻辑提交。
8793 那组要求 deploy-cn 已 sync（`npm run sync`），否则报「层缺失」。

## 4. 写一个浏览器测试（模板）

现有测试都用项目自带的 playwright-core + 本机 Chrome，**不用装依赖**：

```js
const { chromium } = require("E:/育人帮/temp/pw/node_modules/playwright-core");
const CHROME = "C:/Program Files (x86)/Google/Chrome/Application/chrome.exe";
const BASE = "http://127.0.0.1:8796/yurenbang-app.html";

const b = await chromium.launch({ executablePath: CHROME, headless: true });
const p = await b.newPage({ viewport: { width: 412, height: 900 }, isMobile: true, serviceWorkers: "block" });
const errs = [];
p.on("pageerror", e => errs.push(String(e.message)));
await p.goto(BASE + "?t=" + Date.now(), { waitUntil: "domcontentloaded" });
await p.waitForTimeout(1200);
// 启动屏可能挡着，点掉
if (await p.evaluate(() => { const s = document.querySelector("#splash"); return !!(s && !s.classList.contains("hidden")); })) {
  await p.click("#splash");
}
```

要点：
- **每次都带 `?t=Date.now()`**，绕开缓存
- **`serviceWorkers: "block"`**，否则 SW 缓存会让你看到旧代码
- **收集 `pageerror`**，最后断言为 0（比逐个功能断言更能抓住隐患）
- 结果打印 `PASS/FAIL` + 末行 **`结果: N 通过, M 失败`**，`process.exit(fail ? 1 : 0)`
  这个末行格式是**硬约定**：`verify.mjs` 用正则从里面抽用例数，格式不对就只显示「通过」而看不到数量
- 递增的全局名（如 `const URL = ...`）会遮蔽同名的全局对象（`URL` 构造函数），起了 `TypeError: URL is not a constructor` 就把变量改名

## 5. 云端桩（云隔离期的标准做法）

种子假数据已于 2026-10-25 全量下线，**不能再依赖** `S.posts` 里有内容。测试一律自己注桩：

```js
// 注一条帖子并重渲染
await p.evaluate(() => {
  S.posts.unshift({ id: 990002, user: "测试家长", time: "刚刚", tag: "求助",
    text: "测试内容", likes: 1, favs: 0, helps: 0, ava: "animal" });
  renderFeed();
});

// 假装已登录（不碰真云端）
await p.evaluate(() => { const C = window.YRB_CLOUD; C.signedIn = () => true; C.who = () => ({ name: "测试" }); });
```

**桩 id 段位约定**（避免与真实数据/其他测试碰撞）：

| 段位 | 用途 |
|------|------|
| 9101 / 9102 | 普通帖子 |
| 9401 / 9501 | 媒体/案例类 |
| 990001～9901xx | 长图与临时场景 |

## 6. 常见问题

| 现象 | 原因与处理 |
|------|------------|
| `Executable doesn't exist` | Chrome 路径变了，改测试顶部的 `CHROME` 常量 |
| 断言全挂、页面空白 | 服务没起，或起了别的目录（确认 8796 指向 `yurenbang-app/`） |
| 第一次跑很慢 | 首次加载 vendor 里的 PPT 引擎，属正常 |
| 测出来是旧行为 | SW 没拦、或 `?t=` 没加 |
| 图文编辑器测试红 | 必须用真实 pptx（`temp/ppt-test/sample_fixed.pptx`），合成文件引擎不认 |
