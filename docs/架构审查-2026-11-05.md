> 审查口径：科学性（分层与边界是否成立）、流畅性（首屏与滚动成本）、便利性（能不能一眼找到）、体验感（长辈能不能用）。

|------|------|------|

## 二、科学性：分层架构的成色

### 2.1 做得好的地方（这些别改）

1. **层登记四处对齐 + 自动审计**
   加一个层要同时改 `index.html` / `sw.js` CORE / `health.js` LAYERS / `sync_deploy.py` layers，`scripts/layers-audit.mjs` 一条命令验完，还查「文件在磁盘但没进 git」这种真实事故。
   → 这是这个项目最值钱的工程资产，31 个层还能保持一致的根因。

2. **状态契约 + 守卫**
   `state.schema.js` 声明 25 个字段的 owner/writable，`state.js` 在 dev 期拦截越界写入并报出源码行号，生产零开销。
   → 多 IIFE 共享一个全局 `S` 的方案里，这是唯一可规模化的做法。

3. **层叠阶梯 + 审计**
   z-index 分 6 段（0-9 装饰 … 99997-99999 强制提示），超 96 必须登记，`zindex-audit` 守着。
   → 手机端浮层地狱的根治手段。

4. **RLS 与前端门槛双保险**
   前端 gate 只管体验，真权限在数据库（`owner_id = auth.uid()`、`is_admin()`）。
   → 客户端被绕过也不至于丢数据。

5. **推荐算法写成纯函数**
   `YRB_RECO.order(list)` 不依赖 DOM 和网络，12 项断言可复现（同种子同序）。

### 2.2 结构性代价（要认账的部分）

| 项 | 数字 | 影响 |
|----|------|------|
| 功能层数量 | 31 层 | 加载顺序即依赖关系，冲突靠约定不靠类型 |
| 全局通信 | 全部走 `window.YRB_*` 单例 | 层与层之间无法静态分析，改一处要靠 grep |
| 单文件打包 | 805 KiB / 1 个 `<script>` | 首屏为"后台、PPT、案例编辑、美食动画"一起付费 |
| 最大单层 | `cloud.js` 110 KiB、`app.js` 85 KiB、`admin.js` 79 KiB | 单层超 200 KiB 会被审计拦，目前最大 110 KiB 还算克制 |

**可以按需加载的层（首屏完全不需要）合计约 216 KiB：**

```

mediafull 43.0 KiB   媒体全屏 / 播读（点开媒体才用）
```

## 三、流畅性：数字与瓶颈

### 3.1 首屏实测（4 倍 CPU 降速、禁用缓存、直连）

| 站点 | TTFB | FCP | DCL | load | 请求 | 脚本求值 | 长任务 |
|------|------|-----|-----|------|------|----------|--------|
| 育人帮.cn（CF） | 1008 ms | 1428 ms | 2474 ms | 2723 ms | 13 | 1737 ms | 402 ms |
| 境内站（轻量云） | 75 ms | 360 ms | 2276 ms | 3370 ms | 12 | 1585 ms | 0 ms |

读法：
- **境内站 TTFB 75 ms、FCP 360 ms**：服务器和静态托管这一侧已经很好，不用再优化。
- **两站脚本求值都约 1.6 s**：这是 805 KiB 单文件的解析+执行成本，跟服务器无关，是架构成本。
- **CF 站 TTFB 1008 ms**：境外边缘 + 国内网络，属于物理距离，改不了（这也是当初上境内站的原因）。

### 3.2 这轮修掉的

- 图片加载前 `aspect-ratio:auto` 导致占位高度 0，落地瞬间撑开 420 px，快速滑动时整屏反复重排（**上轮已修**）。
- 服务器侧压缩核对：`bundle.js` gzip 后 277 KiB、CSS 46 KiB，nginx `gzip_types` 已含 js/css。
- 补 `gzip_vary on`：原来没开，中间缓存可能把未压缩版本发给支持压缩的浏览器（已加，nginx -t + reload 通过）。

### 3.3 还欠的一笔

bundle 从 799.9 KiB 顶到上限这件事，本轮把守卫改成**双指标**而不是偷偷提额：

```
raw  805 KiB / 860 KiB（解析成本的代表）
gzip 274.6 KiB / 300 KiB（用户真正下载的字节）
```

两条都守，且各自有理由：只看 raw 会误判（805 KiB 听着吓人，实际传 275 KiB），只看 gzip 会放过「压缩率高但解析很重」的重复代码。

### 4.2 两个必须你拍板的缺口

**缺口 A：匿名看不到图片。**
现在未登录时 11 条内容里 11 条媒体都是「🔒 登录后可查看」，一张图都不渲染。这跟「任何用户可以浏览」是有落差的。

- 原因不是前端想拦，是存储桶私有：实测匿名 `sign` 返回 `Either the object does not exist or you do not have access`。
- 要开放有两条路：
  1. **把 `media` 桶改公开**：图片秒出、可被 CDN 缓存（流畅性也一起解决）。代价是**孩子的照片变成"知道链接就能打开"**，这与现有隐私合规口径冲突，需要同步改政策。
  2. **保持私有**（我的建议）：未登录只能读文字。家长群里的传播场景本来就是"点进来看看"，看到文字+「登录后可看图」已经足够判断值不值得注册。
- 若选 1，SQL 与前端改动我可以一并做，但这是一次**隐私口径变更**，需要你明确点头。

**缺口 B：收藏与点赞根本没入库。**
数据库里 `yb_posts.favs` / `likes` 两列一直存在，但客户端**从来没有写过**：

- 收藏只存 `localStorage`，换手机就没了；
- `liked` 每次从云端拉数据都被重置成 `false`，点赞状态刷新即消失；
- 发布者看到的「⭐ 收藏数」永远是 0。

也就是说，「登录才能收藏」刚补上的门槛，后面接的是一个**不落库的口袋**。这是本轮审查里最该修的一条。
修法（需要你在 Supabase 控制台跑一次，服务端密钥不在我手上）：

```sql
-- 1) 收藏关系表
create table if not exists public.yb_favs (
  user_id uuid not null references auth.users(id) on delete cascade,
  post_id bigint not null references public.yb_posts(id) on delete cascade,
  created_at timestamptz not null default now(),
  primary key (user_id, post_id)
);
alter table public.yb_favs enable row level security;
create policy yb_favs_select_own on public.yb_favs for select to authenticated using (user_id = auth.uid());
create policy yb_favs_insert_own on public.yb_favs for insert to authenticated with check (user_id = auth.uid());
create policy yb_favs_delete_own on public.yb_favs for delete to authenticated using (user_id = auth.uid());

-- 2) 计数由触发器维护（与 yb_comments_sync_helps 同一套路，客户端不碰计数）
create or replace function public.yb_favs_sync() returns trigger
language plpgsql security definer as $$
begin
  if tg_op = 'INSERT' then
    update public.yb_posts set favs = favs + 1 where id = new.post_id;
  elsif tg_op = 'DELETE' then
    update public.yb_posts set favs = greatest(favs - 1, 0) where id = old.post_id;
  end if;
  return null;
end $$;
drop trigger if exists yb_favs_trg on public.yb_favs;
create trigger yb_favs_trg after insert or delete on public.yb_favs
  for each row execute function public.yb_favs_sync();
```

跑完告诉我，我把客户端接上（登录后拉自己的收藏、点击写库、失败回滚），并补回归测试。

### 4.3 本轮已修的

- 收藏门槛补齐（卡片 ⭐ 与详情页两处），登录后自动重放这次点击。
- 详情「我也来帮忙」在入口就提示登录，不再先弹一个锁住的面板。
- 分享改成「这一条」：`?p=<id>` 深链，未登录也能打开。
- 换账号清场：收藏/浏览历史存在全站共用键里，家里共用一台手机会串号（第二个账号看到第一个人的收藏）。现在识别到换人就清空这两项，退出登录不算换人。

## 七、测量方法（避免复现踩坑）

1. **必须 `--no-proxy-server`**：本机代理会剥掉 `Accept-Encoding` 并解压后再转发，`encodedBodySize` 于是等于原始大小，会得出「服务器没压缩」的错误结论。这轮就被骗过一次，命令行的原始 HTTP 请求（带 Chrome UA）才是准的。
2. **CPU 降速 4 倍**才有区分度：桌面 GPU 走快速路径，1 倍速下所有方案都是 60 fps，测不出弱机差异。
3. **性能测试要走登录态 + 真实数据**：匿名态媒体是锁的，图片路径根本不会被测到（上一轮找图片重排问题时就白测了一整天）。
4. 光栅化开销用 `PerformanceObserver` 的 `RasterTask` / 强制重绘一次来量，比帧率计数更稳。

## 七、11-05 上午的落地记录（缺口 A / B）

### 7.1 点赞与收藏入库（缺口 B，已改完，等你跑一条 SQL）

一条 SQL 建表即生效，脚本在 **`db/supabase/04-reacts.sql`**（可重复执行）：

- `yb_reacts(post_id, user_id, kind)`，`kind in ('like','fav')`，主键天然防重复；
- 只给 `authenticated` 开放「自己的」行的读/增/删 —— 页面上公开的只有汇总数，
  **不公开谁赞过谁**，陌生人无法反查某个账号的点赞足迹；
- 计数不信任客户端：触发器 `yb_reacts_sync` 在库端回写 `yb_posts.likes / favs`，
  客户端只说「我要 / 我不要」，不自己加减；
- 末尾把两个计数字段按真实关系重算一遍，存量数据自动对齐。

客户端（`cloud.js` / `access.js` / `gate.js`）：

- 登录后从 `yb_reacts` 拉自己的状态，卡片 ⭐ / ♥ 与库里一致；库端计数是「含自己」的，
  客户端先减掉自己那一份，渲染公式（`likes + (liked?1:0)`）一行没动，显示就对得上；
- 写库失败（非「表未建」）**整体回滚**界面与数据并提示，不留下「以为存下了」的假象；
- 表未建时（SQL 还没跑）自动降级为「本机暂存」，不弹错、不挡操作，表建好后无需发版即生效；
- 顺手修掉三个既有缺陷：
  ① 卡片点 ⭐ 只改 `p.faved`，从没写进 `S.favIds` ——「我的收藏」一直是空的；
  ② 详情页点 ♥ / ⭐ 只切 class，`p.liked/faved` 没变，数字也不动，重开详情状态就丢；
  ③ 详情页收藏在**捕获阶段**先改状态，被 gate 拦下重放后变成「取消收藏」。
- 点赞纳入登录门槛（原规则没要求，但不登录的点赞无法持久化，只会造成假数）。

回归：`tests/core/react-test.js` 8 项（未登录拦截 / 点赞写库 / 收藏进夹 / 失败回滚 /
云端回传 / 详情点赞 / 零错误），已进 `npm run verify -- --e2e`；`perm-test` 7/7 仍全绿。

### 7.2 匿名看图（缺口 A，SQL 已备好，待执行）

**`db/supabase/05-storage-guest-media.sql`**：

```sql
create policy yrb_media_guest_read on storage.objects
  for select to anon
  using (bucket_id = 'media' and split_part(name,'/',1) = 'shared');
```

- 桶名是 `media`（从 SDK 发出的真实请求 `/storage/v1/object/sign/media` 里读出来的，
  不是猜的）；素材路径形如 `shared/<uid>/<类型>/<时间戳-序号-随机>.<ext>`；
- 只加 SELECT：匿名能取「已知路径」的一张图，不能上传、不能删除、不能覆盖；
- 前端 `signPaths()` 已不再要求登录会话，放开后匿名**无需发版**即自动看到图；
  没放开时静默失败，卡片照旧显示「🔒 登录后可查看」。
