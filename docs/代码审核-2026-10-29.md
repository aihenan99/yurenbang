## 二、高危（按建议修复顺序）

### H1. 【铁律未落实】S.posts 原地 unshift，违反「只许整体替换」铁律 ✅已修复（含 cases 两处 + 审计黑名单）
- schema:58-61 明文铁律，但 `refine23.js:455`（`S.posts.unshift(p)`）、`access.js:41` 违反；
  `app.js:328` 是唯一合规写法。静态审计正则不认方法调用黑名单，54 处全绿=无人执行。
- 修法：state-audit 加 unshift/push/splice 黑名单（一行），两处改 `[p,...S.posts]`。**投入产出比最高的一刀。**

### H2. access 层动态写法越权改 `S.roses`，同时绕过静态审计 ✅已修复（schema 正名 access + limits 记录动态写盲区）
- `access.js:31` 动态 `S[k]=` 恢复 roses，schema owner 是 app/reward；静态审计只认字面 `S.roses` → 三道防线全盲。
- 修法：从恢复列表删掉 roses（或正式把 access 加进 writable）。

### H3. /yrbapi 是「无同源校验的开放中继」，可被脚本借道刷验证码短信 ✅已核实
- `_worker.js:367-395`：对任何调用方一律改写 Origin 转发上游，唯一闸门是限流（且见 H4）。
  cloud.js:616 证实上游暴露 `/.cloud/auth/v1/verification` 端点 → 任意脚本可向任意手机号刷短信，
  部署包里又有明文管理员号（M3），可被针对性轰炸。
- 修法：/yrbapi 加 `Origin/Referer ∈ 本站` 同源校验（应用恒同源，不影响正常流量）；
  `/.cloud/auth/` 子路径单独收紧限额。

### H4. 限流是「每 isolate 进程内 Map」＝限额×实例数；IP 缺失时兜底常量并桶
- `_worker.js:329-337,354`。攻击可用 Header 洪水把正常用户顶成 429（反向 DoS）。
- 修法：短期把 IP 兜底从「常量桶」改为「放行+记日志」；长期 Durable Object/KV 全局计数。

### H5. protect 层杀死 longimg 分享长图的保存路径（微信场景核心功能失效）✅已修复（白名单加 .lg-scroll img）
- `protect.css` 的 `html.yrb-guard img{pointer-events:none;-webkit-touch-callout:none}` 白名单不含 `.lg-scroll img`；
  长按保存落空 + 右键被 `protect.js:64` 拦；Web Share 在微信内不可用 → 长图无法保存转发。
- 修法：白名单加 `.lg-scroll img`（`pointer-events:auto;-webkit-touch-callout:default`），一行。

### H6. longimg 画布恒 1500×13600≈2000 万像素（约 81MB），超旧 iOS 上限且短帖也全额分配
- `longimg.js:165-166,276-277`。旧 iOS Safari 16.7M 像素上限 → toDataURL 失败出白图。
- 修法：第一遍测量后按实际内容高度建画布。

### H7. e2e 门禁系统性假绿：本机可跳过、CI 根本跑不了
- `verify.mjs:297-316` 服务没起=整组跳过且 exit 0；CI 只跑 fast+标准；10 个 e2e 硬编码 Windows Chrome 路径。
- 修法：Chrome 路径环境变量化 + CI 用 playwright chromium 强制跑 e2e（跳过≠通过）。

### H8. SW 预缓存 addAll 原子失败被吞 + CORE 无缓存戳 → 可能「零缓存上线」
- `sw.js:42-44` 空 catch；Pages 默认 4h 资产缓存可能让 install 写入旧 bundle；
  新 SW activate 先删旧缓存 → 用户从有缓存变零缓存。另 `yurenbang-app/sw.js:13` 源码版引不存在的 bundle（源码线离线能力为零）。
- 修法：allSettled 逐文件缓存+失败上报；CORE URL 加 `?v=构建号`；源码版清单去 bundle。
