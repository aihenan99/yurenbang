## 一、自动防线（已生效，无需人工）

| 防线 | 位置 | 触发 | 失败后果 |
|------|------|------|----------|
| 工程门禁 | `.githooks`（pre-commit `--fast` / pre-push 标准） | 每次提交/推送 | 拦住提交 |
| 远端兜底 | `.github/workflows/verify.yml` | push / PR | PR 变红 |
| 依赖漏洞 | `.github/workflows/security.yml` → `npm audit --audit-level=high` | push / PR / 每周一 05:17 | 变红 |
| 泄密扫描 | 同上 → gitleaks（全历史） | push / PR / 每周一 | 变红 |
| 响应头实测 | `scripts/worker-headers.mjs`（verify 内） | 每次 verify | 13 项任一不合格即失败 |
| CSP 强制演练 | `scripts/csp-rehearsal.mjs` | 手动 `npm run verify:csp` | 有违规即失败 |
| 源码零手机号 | `scripts/verify.mjs` 仓库卫生 | 每次 verify | 出现即失败 |

本地两条常用命令：

```bash
npm run audit:deps     # 依赖审计（当前零依赖，是"将来加依赖"的哨兵）
npm run verify:csp     # CSP 转强制演练（需本机 Chrome，约 20 秒）
```

gitleaks 的误报豁免在 `.gitleaks.toml`：只放行「本就是公开值」的三类
（IndexNow 站点校验 key、tests/docs 里的假占位、cloud.js 的公开平台标识）。

## 二、GitHub 侧必须手动打开的两项（一次性，约 2 分钟）

workflow 打不开仓库安全开关，只能在网页点：

1. 打开 https://github.com/aihenan99/yurenbang/settings/security_analysis
2. **Secret scanning**：设为 Enabled（公开仓库通常已默认开启）
3. **Push protection**：设为 Enabled —— 这一项最关键，它能在密钥**推上去之前**拦下来
4. （建议）**Dependabot alerts** 设为 Enabled，与 `npm audit` 形成双保险

验证：Security 页签出现 "Secret scanning" 区域并显示 "No secrets found"。

## 三、管理员手机号：已移出源码

| 项 | 值 |
|----|-----|
| 私有配置 | `config/admin.local.json`（`{"phones":[...]}`，`config/` 已 gitignore） |
| 注入时机 | `npm run sync` 把 `window.YRB_ADMIN={"phones":[...]}` 前置到**部署包** `admin.js`（以及 bundle） |
| 源码 | `ADMIN_PHONES = (window.YRB_ADMIN && window.YRB_ADMIN.phones) \|\| []`，零手机号 |
| 主判据 | `ADMIN_IDS`（`auth.users.sub`），不依赖手机号；配置文件缺失也不影响管理员识别 |
| 防回潮 | verify 仓库卫生扫描全部受管源码，出现配置里的号码即失败 |

**必须清楚的边界（别自我安慰）**：

1. **部署产物仍是公开 JS**，手机号注入后任何访客都能在 bundle 里看到。
   真正的权限从来不在前端——`admin.js` 只是界面入口，写操作由数据库 RLS / `is_admin()` 把关。
   本次改动的收益是「**公开仓库源码零号码**」，不是「号码不可见」。
2. **历史提交里仍有该号码**。要真正抹掉需重写历史 + 强推，与 main 分支保护冲突，
   收益（号码早已公开多年）不抵风险，**不做**。彻底解决靠下面第 4 条。
3. `tests/diag` 里少数**真机登录探针**（`otp_live_check` / `admin_visibility_check` /
   `proxy_check` / `sdk-debug/*`）仍含号码——它们是本机工具，改成假号就失去意义。
   桩会话类测试已全部换假号（`18000005855`）。
4. 彻底方案：**云端 `is_admin()` RPC**，前端只问"我是不是管理员"，号码永不出现在客户端。
   等 11 月额度恢复后做（见《恢复后待办.md》第零步）。

## 三·五、已知暴露面：内部工作笔记曾进公开仓库（**已处置：只停止入库**）

发现于 2026-10-28：把泄密扫描从「只扫本次推送」改成「扫全部历史」后暴露。
**2026-10-29 已按方案 2 处置**（作者示意「开工」，按最小破坏原则执行）：

- ✅ `.workbuddy/` 已移出 git 跟踪（`git rm -r --cached` + `.gitignore` 加 `.workbuddy/`），
  **本地文件原样保留**，此后笔记只存本地
- ✅ gitleaks 白名单保留 `\.workbuddy/memory/` 路径条目——历史提交里仍有旧版本，撤掉会误报
- ⬜ 历史里的号码不追改：见下「历史清理」结论（不建议 filter-repo + 强推）
- ⬜ 若想更进一步（方案 1 的后半）：把本地 3 个日志里的号码改成 `180****5855`——
  号码本体在 `config/admin.local.json`（gitignore），随时可查，收益有限按需再做

### 原始事实（存档）

- 曾有 22 个 `.workbuddy/` 文件被 git 跟踪，仓库是 **public**；
  其中 5 个 memory 日志含管理员手机号（`2026-10-14/15/16/23/28.md`，严格 11 位口径）
- 另有 8 个文件含号码但不是笔记：`temp/probe_reset.py`（本机探针）、
  `tests/diag/` 下 7 个真机登录探针（`admin_visibility_check` / `cors_probe` /
  `otp_live_check` / `proxy_check` / `sdk-debug/*`）

**为什么之前的守卫没拦住**
`npm run verify` 的「源码零手机号」只扫 `yurenbang-app/`、`scripts/`、`docs/`、根目录文档与
`deploy-cn` 的两个人工源文件——`.workbuddy/` 与 `tests/` 不在范围内。
**已补**：同一把针现在也扫全部 git 跟踪文件；对非源码文件只**每次点名提示**、不拦构建。
（移出跟踪后 `.workbuddy/` 不再进针的扫描面，提示自然消失。）

**历史清理**：号码已在公开历史的多个提交里。抹掉要 `filter-repo` + 强推，
与 main 的 `block force pushes` 冲突，且可能已被镜像抓取——收益不抵风险，不建议做。
真正的解法仍是 **云端 `is_admin()`**：号码从客户端彻底消失，历史里那串数字才不再有利用价值。
