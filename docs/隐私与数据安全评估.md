# 隐私与数据安全评估（2026-10-28）

> 审计对象：`yurenbang-app/`（27 层）+ `deploy-cn/_worker.js` + `db/schema.sql`。
> 方法：代码走查 + 数据流追踪（收集→存储→展示→删除）+ 对照《个人信息保护法》《未成年人网络保护条例》
> 与常见第三方审核口径。**本文所有结论都有代码位置，可复核。**

## 一、结论（先说能不能过审）

| 维度 | 判断 | 说明 |
|------|------|------|
| 技术防泄露 | **较好** | 签名地址限时、手机号脱敏、RLS 分层、零第三方分析 SDK、零硬编码密钥 |
| 隐私告知文本 | **形似而神不至** | 有政策正文，但缺 PIPL 必备条款；有 3 处"承诺了但没实现" |
| 第三方审核 | **现在过不了** | 三个硬门槛：① 备案/境内托管 ② 注销与虚假信息 ③ 儿童个人信息机制 |

**一句话**：技术上比多数同类站干净，但**合规上存在"说了做不到"的硬伤**——这在审核里比"没写"更严重。

### P0-1 注销账号是假入口（承诺未兑现）

- **状态**：⬜ 未整改（依赖云端 `SECURITY DEFINER` RPC）。
  入口已先撤掉，不留"点了没反应"的按钮；政策与协议均已改为"过渡期经反馈渠道人工处理"的如实表述。

- **现象**：`app.js:482` 把「注销账号」写成静态设置行，全项目**没有任何注销逻辑**
  （`grep 注销` 只命中隐私政策文案）。而政策 `cloud.js:674` 明确承诺"注销后 15 个工作日内删除或匿名化"。
- **合规**：PIPL 第 47 条（删除权）+ 第 15 条（撤回同意）；审核方只要点一次就发现。
- **整改**：云端加 `yb_account_delete()` SECURITY DEFINER，级联删除 `yb_posts/yb_comments/yb_cases/yb_gifts/yb_profiles/yb_accounts` + `storage.remove` 素材 + `auth` 用户；前端加二次确认 + "7 天冷静期可撤回"；删除留**不可逆审计凭证**（只记 ID 哈希与时间，不留内容）。

### P0-2 设置页展示虚假状态（比缺功能更致命）

- **状态**：✅ 已整改（2026-10-28）。三行全部删除，我的页「已实名」标签与 `cloud.js` 动态挂载逻辑同步移除。
- **现象**：`app.js:482` 写死「手机号 138****8888」「微信绑定 已绑定」「实名认证 已认证」；
  实际手机号非此号、微信登录未必开通、**平台根本没有实名认证流程**。
- **合规**：《反不正当竞争法》虚假宣传 + 个人信息处理"告知真实"；应用市场审核会按截图核对功能。
- **整改**：三行全部改为**真实数据驱动**——手机号取 `who().phone` 经 `maskPhone`；微信绑定显示真实绑定态；
  实名认证**要么接入真实核验，要么整行删除**（"已认证"字样的风险远大于收益）。

### P0-3 隐私设置四个开关是装饰（虚假控制权）

- **状态**：✅ 已整改（2026-10-28）。按"宁可不有，不可假有"——四个开关全部撤掉，`privacy` 子页改为「隐私与个人信息」，只放三个真实可读入口。
- **现象**：`app.js:483` 的「公开我的求助 / 允许陌生人评论 / 个性化推荐 / 同城可见」只切换 UI，
  无任何读写逻辑；`S` 里也没有对应字段（`state.schema.js` 契约里没有）。
- **合规**：让用户以为能控制处理范围，属误导；且"个性化推荐"暗示存在算法推荐，实际没有。
- **整改**：两周内二选一——**实现**（`public/comments_open/tongcheng` 落 `yb_profiles`，查询与评论 RLS 联动）
  或 **隐藏**（先删行，恢复后随版本补）。宁可没有，不可假有。

### P0-4 隐私政策缺 PIPL 必备条款

- **状态**：✅ 已整改（2026-10-28）。`LG_DOCS.privacy` 已换成 v2.0 正文，下表缺项逐一补齐；未确定的事实项（主体名称、邮箱、备案号、负责人、机房区域）一律标注"待补充"，不虚构。

现有 v1.0（`cloud.js:669-680`）覆盖了收集项/用途/共享/存储/安全/权利/未成年人，但缺：

| 缺失项 | 依据 | 审核后果 |
|--------|------|----------|
| 处理者**身份与联系方式**（现只有 `support@yurenbang.example` 演示邮箱） | PIPL 17 | 直接不合格 |
| 个人信息保护**负责人**及联系方式 | PIPL 52 | 规模小可豁免，但要写明"未指定"的理由 |
| **第三方 SDK 清单**（名称/收集内容/用途/其隐私政策链接） | 审核通用要求 | 直接不合格 |
| **敏感个人信息单独同意**（14 岁以下、位置、语音） | PIPL 29/31 | 直接不合格 |
| **跨境传输**事实与依据 | PIPL 38-39 | 高风险，见 P0-5 |
| **安全事件通知**机制 | PIPL 57 | 缺项 |
| **生效日期 / 版本历史** | 审核通用要求 | 缺项 |
| **投诉渠道**（含网信办 12377 等外部渠道） | PIPL 50 | 缺项 |

→ 已按此补齐：`docs/隐私合规/隐私政策-v2.md`（可直接替换 `LG_DOCS.privacy`，待法务复核）。

### P0-5 "存储于中国境内"可能与事实不符（最大法律风险）

- **状态**：✅ 表述已整改（2026-10-28）。政策改为如实说明：静态资源经 Cloudflare 全球边缘分发（节点可能在境外）、数据库与文件机房位置待确认、若涉跨境按 PIPL 38/39 履行告知与单独同意。**书面托管证明仍需云恢复后向服务商索取**。
- **现象**：政策写"信息存储于中国境内的服务器"（`cloud.js:674`），但实际部署是
  **Cloudflare Pages**（静态资源全球边缘分发）+ workbuddy 云服务（区域未确认）。
- **判断**：静态资源不含个人信息尚可解释，但**请求日志（IP/UA）会落在境外边缘节点**；
  若云数据库不在境内，则该句是**虚假陈述**。审核（尤其备案与等保）会要托管证明。
- **整改**：① 立刻向云服务商确认数据库区域并留证；② 政策改为**如实表述**（境内/境外分别说明，
  并写明跨境所依据的法定路径）；③ 若确需境内合规，按《迁移评估-Cloudflare-D1R2.md》走境内托管。

### P1-1 14 岁以下未成年人：只有文案，没有机制

- **现象**：政策与服务协议都写"未满 14 周岁须监护人代为操作"，但**没有年龄采集、没有监护人同意、没有儿童信息专门规则**。
  平台内容大量涉及未成年人 → 这几乎是审核必查项。
- **依据**：PIPL 31（14 岁以下为敏感个人信息，须监护人**单独同意**）+ 《儿童个人信息网络保护规定》。
- **整改**：① 发布涉及儿童内容时弹"监护人确认"勾选（留痕：时间 + 账号 + 版本）；
  ② 儿童信息默认不公开索引（`robots` 与列表页都不出）；③ 单独规则文本见 `docs/隐私合规/儿童个人信息处理规则.md`；
  ④ 接到删除请求 72 小时内下架（比一般情形更严）。

### P1-2 SDK 从境外 CDN 加载

- **状态**：✅ 已整改（2026-10-29）。SDK 随站点同源部署（`assets/vendor/cloud-sdk.global.js`，SW 离线缓存），unpkg/jsdelivr 兜底彻底下线——同源+SW 缓存已必达，境外兜底只剩 IP/UA 出境负担。
- **原现象**：`cloud.js` 从 unpkg / jsdelivr 拉 SDK，用户 IP/UA 暴露给境外 CDN，国内可用性差（当初"打不开"的原因）。
- **整改**：SDK 落到 `assets/vendor/`（与 pptx-preview 同法），`connect-src 'self'` 收紧才有意义。

### P1-3 数据资产未登记 / 举报人信息明文

- `yb_accounts`（用户名→**明文手机号**映射）未进 `db/schema.sql` 契约 → 隐私数据资产没台账，删号时容易漏删。
- 举报列表对管理员显示 `reporter_name`（`admin.js:238`）→ 处理举报属必要，但应脱敏为"家长****"并记审计日志。

### P2 其它（不影响过审，影响体验与口碑）

- 政策宣称保存"浏览历史、收藏"——实际浏览历史在 `S.history`（随档案持久化）、收藏仅在内存，**表述需与实际一致**。
- 无**个人信息导出**（可携带权）：现仅"反馈与帮助"人工处理，建议加"导出我的数据（JSON）"。
- 无日志留存策略：等保要求网络日志 ≥6 个月，Cloudflare 侧留存需确认并写进制度。

## 五、一句话给审核方的话术

> "我们只收集手机号（登录）、用户主动发布的内容、以及必要的设备与错误日志；
> 不接广告与统计 SDK，不做用户画像；媒体一律限时签名地址；删除与注销有明确时限与留痕；
> 涉及未成年人的内容有单独规则与更短处置时限。"

这段话现在**约 85% 能兑现**："删除与注销有明确时限与留痕"仍是过渡期人工处理（P0-1 待云恢复）。
上一轮整改把虚假状态、装饰开关、政策缺项、境内存储表述四类问题清掉了——
它们不再靠自觉，而是 `npm run privacy:audit`（10 项回归）与 `tests/core/privacy-test.js`（16 项端到端）持续守着。
