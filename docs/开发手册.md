# 开发手册（新人 1 天上手）

> 配套阅读：`ARCHITECTURE.md`（架构与加载序）、`工程总纲.md`（里程碑与工作流）。
> 目标读者：第一次接手育人帮代码的人。照本文做完，你能本地跑起来、改对地方、不踩已知坑。

---

## 1. 五分钟跑起来

**依赖**：Node ≥18、Python 3、本机 Chrome（测试用）。
项目**没有 npm 依赖**（工具全是 Node 内置模块），clone 下来就能用。

```bash
npm run serve          # 起源码服务 → http://127.0.0.1:8796/yurenbang-app.html
```

三个端口别混：

| 端口 | 目录 | 用途 |
|------|------|------|
| **8796** | `yurenbang-app/` | 源码直跑，改完刷新即见（端到端测试也认这个） |
| 8794 | `deploy-cn/` | 部署包预览（验证 sync 产物） |
| 8793 | 项目根 | 走 `/deploy-cn/` 访问，便于对照 |

打开后若见启动屏，点一下即可；云服务隔离期会显示「云端维护」，属正常。

## 3. 三分钟看懂架构

前端是**多脚本叠加**，不是打包应用：`app.js` 是核心（内含顶层 `const S` 全局状态），
其后每一层都是「增强层」——只做注入与事件委托，**不改 app.js / refine23.js 的结构**。
完整加载序见 `ARCHITECTURE.md` 的表；记住三条铁律：

1. `cloud.js` 必须在 `refine23` 之后；任何层读 `YRB_CLOUD` 都要**运行时**取，不能加载时缓存。
2. `health.js` / `upgrade.js` 必须最后加载（要能探到全部层）。
3. 新增层要同时改**五处**（见下），漏一处弱网里就会悄悄消失。

## 4. 新增一个功能层（标准动作）

以 `longimg`（分享长图）为范例，按顺序做：

1. 写 `yurenbang-app/assets/你的层.js` + `.css`，IIFE 包裹，挂 `window.YRB_XXX`
2. `yurenbang-app.html` 引用 css（`</head>` 前）与 script（按依赖顺序，health/upgrade 之前）
3. `sw.js` 的 `CORE` 清单加两条（离线缓存）
4. `assets/health.js` 的 `LAYERS` 加一条（severity + probe）
5. `temp/sync_deploy.py` 的 `layers` 数组加名字（build.json 元信息）
6. `ARCHITECTURE.md` 层表加一行
7. `npm run verify` → 绿了再提交

**增强层纪律**（血泪教训）：
- 只注入 DOM + 委托事件，不重写别人的渲染函数
- 用户文本进 `innerHTML` 前必须过 `esc()`
- 注入必须幂等（用 `data-xxx` 标记 + 查重），否则 MutationObserver 会死循环
- 浮层显隐统一 `.open`/`.show`；z-index 不得超 `#modal` 的 96

## 5. 状态边界（改 S 之前必看）

`const S` 是核心状态对象（词法全局，**不是** `window.S`）。它的字段契约在
`assets/state.schema.js`（25 字段，标注 owner / writable）。

```bash
npm run audit:state    # 静态审计：谁在写不该写的字段
# 浏览器里加 ?stateaudit=1 可实时看每次写入的来源层与行号
```

新增字段流程：先在 schema 登记（owner、writable、note），再写代码。不登记 = 审计红。

## 6. 与云端交互

- **唯一出口** `YRB_CLOUD`（cloud.js）。数据库调用必须 `YRB_CLOUD.client.database.from()`，
  `client.from()` 会静默失败（踩过）。
- SDK 是异步加载的：禁止 `if (!C.client) return` 直接放弃，要等 `yrb-cloud-ready` 事件或轮询。
- 新增「要登录才能用」的入口，记得补 `gate()`（看内容免费、互动需登录）。
- 云隔离期（当前状态）：**不要发版**，本地用桩开发，见测试手册第 4 节。

## 7. 发布（只此一条路）

```bash
npm run sync      # 源码 → deploy-cn（自动补域名适配，会跑 65 项校验）
npm run deploy    # 唯一发布入口：备份 → 校验 → 部署 → 自检 → 失败自动回滚
```

**禁止手动 cp 同步**——域名适配（`.cn`、`/yrbapi`、canonical）会被覆盖，历史上踩过 4 次。
发布必须后台跑（`run_in_background`），前台会超时中断。

## 8. 已知坑速查

| 现象 | 原因 | 处理 |
|------|------|------|
| 改了 S 但页面读不到 | 用了 `var S` 遮蔽词法全局 | 用 `const`/直接引用 |
| 某层在弱网消失且无人补 | 五处登记漏了（尤其 sw/health） | 按第 4 节补全 |
| 新浮层盖不住或盖住登录框 | z-index > 96 | 降到 90 附近 |
| 卡片操作列按钮重复 | 注入未做幂等 | 查 `data-xxx` 标记 |
| 视频点不动 | protect.css 覆盖了 pointer-events | 保持 `pointer-events:auto` |
| 部署后仍跑旧脚本 | 忘了换构建号戳 | 走 `npm run sync`，别手工改 |
| sync 后 worker 里注释标记越积越多 | 旧版注入 bug（已修） | 重跑 `npm run sync` 自动收敛 |

## 9. 提交规范

- 提交前钩子自动跑快速档；推送前跑标准档；远端 Actions 再兜一遍。
- 提交信息：`feat:` / `fix:` / `docs:` / `refactor:` + 一句中文说明（说清「为什么」）。
- `main` 已开分支保护：禁强制推送、禁删除；日常仍可直推。
- 换机器后第一件事：`npm run hooks`（装上钩子）。
